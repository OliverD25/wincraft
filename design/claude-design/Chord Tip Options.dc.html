The chord tip with real keys

A host feature: every chord shows it, QuickJump's and the ones set in Settings → Hotkeys. It replaces the old one-line "WinCraft: <keys>, waiting for the next key" panel. The right end names WinCraft, so the user sees who is holding the keys. Colours are theme tokens, so it follows the theme, light or dark.

  • Panel. 620 wide, bottom centre of the monitor with the mouse, 24 px above the work area. Elevated fill at 96 %, 1 px rim, window radius, the shared panel shadow. Never takes focus.
  • First line. Keys so far as accent keycaps, "+", then the empty dashed keycap with three moving dots (the border does not pulse). Right end: "WinCraft" 14 px text disabled, 12 px gap, "Esc Cancel".
  • Key list. Two columns, rows 34, keycap 26 then the text, cut with "…". QuickJump: one row per pinned window first ("1 Wincraft": label, else window title, else app), a hairline, then "` Open quick access", "A Add this window", "Alt+1–0 Put this window at a number", "U Unpin this window". The pin shortcut (when it has keys): "1–0 Put this window at a number", "A Add this window", "` Open quick access", "U Unpin this window". A chord from Settings → Hotkeys: its second keys and their commands' names, in the order set there.
  • Bar. 3 px accent on a faint track, inset by the corner radius at both ends, empties over the wait.
  • Timing. A chord that matches or is cancelled within 150 ms shows nothing. A key with nothing assigned shows the red state even then, and is kept from the app in front for host chords too. The first key again (Win+` twice) still goes to Windows.
  • Red state (danger colour, 1.2 s): "Nothing assigned to X", "Quick access is full", "Already number N", "Not in Quick access", "There is no window to pin". A key that makes a change with Undo removes the tip at once; the notice takes its place at the same spot.
